# LightPrism Demo 开发计划 v1.0

> 日期：2026-11-11 · 目标：**做出一个能真跑通的 demo 模型** —— 输入 prompt，输出光明代码或 JSON，
> 在 8GB 内存的第 5 代酷睿 CPU 上推理，**≥ 200 token/s**。
> 本文是任务拆解的唯一事实源；具体任务卡见 `任务书-20261111-LightPrism-Demo/`。

## 一、先说三个定死目标的硬事实（都是实测，不是估计）

### 1.1 200 tok/s 决定了模型规模上限：约 3.4M 参数

在本机（Xeon E5-2643 v2 @3.5GHz，12 线程，**无 AVX2**）用 `torch` 实测逐 token decode 的合成基准：

| d | FFN | 层数 | 单 token | 估算 tok/s |
|---:|---:|---:|---:|---:|
| 128 | 320 | 4 | 1.77 ms | **564** |
| 192 | 512 | 6 | 3.53 ms | **283** |
| 256 | 704 | 6 | 5.34 ms | 187 |
| 256 | 704 | 8 | 7.05 ms | 142 |
| 320 | 832 | 8 | 9.47 ms | 106 |
| 384 | 1024 | 8 | 14.89 ms | 67 |
| 512 | 1344 | 8 | 248.82 ms | 4 |

**结论：demo 模型定在 `d=192 / L=6 / H=6`，词表 4096，约 3.4M 参数。**
本机实测 283 tok/s，留 40% 余量给目标机（第 5 代酷睿单核更强、且有 AVX2）。

`d=512` 那一行掉 20 倍是 cache 溢出（L3 只有 25MB 且被 12 线程分食），
提示**必须盯 working set 而不是参数总量**。

### 1.2 语料只有 3.1MB / 508 个文件

`light/` 仓下 `.light` 文件共 514 个、3.13MB，去重后 508 个。
这是**全部**可用的光明代码语料。3.4M 参数的模型在 3MB 语料上会严重过拟合 ——
所以 demo 的目标**不是通用能力**，而是：

- 能稳定输出**语法合法的光明代码 / 合法 JSON**；
- 能对**见过的任务类型**（排序、文件处理、CLI 工具）给出可用代码；
- 速度达标、内存达标、可复现。

**不要指望它做没见过的任务。** 这是 3MB 语料与 3.4M 参数的物理上限。

### 1.3 本机 CPU 比目标机更老

本机是 2013 年 Ivy Bridge（AVX/F16C，**无 AVX2**），目标机是第 5 代酷睿（Broadwell，**有 AVX2**）。
所以在本机测出的 283 tok/s 是**保守下界**。但反过来：不能拿本机数字当验收，
必须在计划里安排一次**目标机实测**，否则「8G 内存 5 代酷睿」这个承诺没被验证过。

## 二、Demo 的验收标准（可执行、可复现）

```bash
cd lightprism && make demo        # 或 python -m lightprism.demo --prompt "..."
```

| # | 标准 | 判据 | 谁来验 |
|---|---|---|---|
| V1 | 能加载模型并推理 | `lightprism chat --prompt "..."` 输出非空 | 自动 |
| V2 | 输出语法合法 | 生成的光明代码经 `light ai check` 无 error 级诊断 | 自动 |
| V3 | JSON 模式合法 | `--format json` 输出可被 `json.loads` 解析 | 自动 |
| V4 | 速度 ≥ 200 tok/s | 单线程 decode，测 200 token 取平均 | 自动 |
| V5 | 内存 ≤ 8GB | RSS 峰值（模型 + KV cache + 运行时） | 自动 |
| V6 | 目标机实测 | 在真 5 代酷睿机器上跑 `bench.py` 达标 | **人工** |
| V7 | 可复现 | `make demo` 从零到出结果 ≤ 10 分钟 | 自动 |

**V4 的口径必须写死**：单线程、贪心解码、prompt 长度 32、生成 200 token、去掉前 10 token 预热。
不写死口径的「200 tok/s」是假的。

## 三、为什么 MVP 不走 64K 词表

方案书里的 64K 是**目标形态**，不是 demo 形态。理由：

1. 64K 词表 → 嵌入层 `65536×192 = 12.6M` 参数，比整个模型还大，且 200 tok/s 下
   每 token 要对 64K 做 softmax（实测占 decode 时间 15%+）；
2. 3MB 语料根本填不满 64K 词表，绝大多数 token 永远学不到。

**demo 用 4096 词表**（光明 L0 44 字 + 高频语法组合 + 标准库名 + ASCII）。
64K 词表的训练在 demo 验收通过后作为独立任务推进，不阻塞 demo。

## 四、任务拆解（6 张卡，3 条可并行）

依赖关系：

```
T-AP-01 语料与词表构建 ──┐
                         ├─→ T-AP-03 训练（出 checkpoint）──┐
T-AP-02 模型与推理核 ────┘                                  ├─→ T-AP-05 验收与目标机实测
                                                            │
T-AP-04 数据配比与增强（与 03 并行，喂 03 第二轮）──────────┘
T-AP-06 文档与打包（全程并行，最后收口）
```

| 卡号 | 标题 | 依赖 | 可并行 | 产出 |
|---|---|---|---|---|
| **T-AP-01** | 语料清洗与 4096 词表构建 | 无 | ✅ 可与 02 并行 | `data/corpus/*.txt`、`vocab_4096.json`、词表统计报告 |
| **T-AP-02** | 模型与推理核（d=192/L=6） | 无 | ✅ 可与 01 并行 | `model_cfg` 新档、KV cache、单线程 decode 路径、`bench.py` |
| **T-AP-03** | 训练出 demo checkpoint | 01 + 02 | ❌ 串行 | `checkpoints/demo-3m/model.pt`、训练日志、loss 曲线 |
| **T-AP-04** | 数据配比与 JSON 任务集 | 无（与 03 并行） | ✅ | `data/sft/`、JSON 输出任务集、格式约束 |
| **T-AP-05** | 验收与目标机实测 | 03 | ❌ | `docs/Demo验收报告.md`、V1—V7 逐条结论 |
| **T-AP-06** | 文档与一键 demo | 无 | ✅ 全程 | README demo 段、`Makefile`、`docs/Demo使用.md` |

### T-AP-01 语料清洗与 4096 词表构建

**为什么单独一张卡**：词表是全局约定，01 没定死之前 02 的嵌入层尺寸、03 的 token 化都无法开工。
这是唯一必须**最先完成**的卡（虽然可与 02 并行，但 03 卡死等它）。

要点：

- 从 `light/**/*.light` 抽 508 个去重文件，剔除 `tests/`、`archive/`、生成产物（`bootstrap/` 里的自举产物要单独判断）；
- 词表按方案书 §3 的分层：L0 44 字（一字一 token，硬约束）→ 高频语法组合 → 标准库名 → ASCII → 控制 token；
- **必须复用 `lightprism.vocab.check_l0_atomicity()`** 验证「一字一 token」；
- 输出 JSON：`{"tokens": [...], "kind": "l0|syntax|stdlib|ascii|control", "counts": {...}}`；
- 统计报告要含：各层条数、语料覆盖率、UNK 率（目标 < 1%）。

验收：`lightprism vocab check vocab_4096.json` 通过；UNK 率 < 1%；L0 原子性通过。

### T-AP-02 模型与推理核

**为什么单独一张卡**：200 tok/s 是工程问题不是训练问题，必须在训练前就把推理路径打通，
否则训完发现速度不达标就白训。

要点：

- 新增 `PrismConfig` 小档：`d=192, L=6, H=6, vocab=4096, max_seq=512`；
- **KV cache**：当前 `model.py` 每次全量重算，decode 是 O(T²)，必须加 KV cache 才可能达标；
- `bench.py`：单线程、贪心、prompt 32、生成 200、去预热 10；
- 实测本机数值写进报告，作为目标机对比基线。

验收：`python bench.py --model demo-3m` 报 tok/s，本机 ≥ 250（留余量给目标机达标 200）。

### T-AP-03 训练出 demo checkpoint

要点：

- 数据：01 的语料 → 03 做 next-token 训练（阶段一「词表共存」）；
- 复用 `train.py`，但**必须先修 `grad_accum` 的串行累加问题**（当前没有 all-reduce，
  单机无所谓，但要在日志里说清）；
- 3MB 语料 + 3.4M 参数，CPU 上应能在数小时内收敛到可生成语法合法代码；
- 产出 loss 曲线（train/val 分开，val 从语料留 5%）；
- **过拟合是预期的**：报告里必须写清「val loss 何时开始上升」，那才是真实能力边界。

验收：`checkpoints/demo-3m/model.pt` 存在，加载后能生成非空序列，val loss 报告在文件里。

### T-AP-04 数据配比与 JSON 任务集

**注意：这张卡与 03 并行，但它的产出喂给 03 的第二轮**。第一轮 03 只用语料本身。

要点：

- JSON 输出任务：构造 200—500 条「prompt → JSON」样本（如「列出三个文件的名称和大小」→ `{"files":[{"name":...}]}`）；
- 格式约束：训练时把 JSON 的 schema 前缀也作为序列的一部分，让模型学会先输出 `{`；
- 决策/验证 token 的配比按方案书 §6 阶段一（控制 token 权重 1.0）；
- **不要造超出 3MB 语料能力的数据**：编造 10 万条任务描述只会让模型背台词。

验收：`data/sft/json_tasks.jsonl` 存在且通过 `load_jsonl` 校验，条数与来源写进报告。

### T-AP-05 验收与目标机实测

要点：

- 逐条跑 V1—V7，结果写进 `docs/Demo验收报告.md`，**每条都要贴命令与真实输出**；
- V4 用 `bench.py` 的标准口径，不许改口径；
- V5 用 `/proc/self/status` 的 VmHWM 而不是 `ps` 的瞬时 RSS；
- V6 必须真的在 5 代酷睿机器上跑（本机不是）。**如果拿不到那台机器，V6 标 `blocked` 并说明**，
  不许拿本机数字冒充。

### T-AP-06 文档与一键 demo

要点：

- `Makefile`：`make demo` / `make bench` / `make check`；
- README 增加「五分钟跑通 demo」段，含真实输出样例；
- `docs/Demo使用.md`：怎么换 prompt、怎么换 format、报错怎么办。

## 五、分派建议

按 hive 的能力匹配：

| 卡 | 建议 agent | 理由 |
|---|---|---|
| T-AP-01 | 任意 `code` + `python` | 纯数据处理 |
| T-AP-02 | 有 `python` + 性能调优经验 | 要测 tok/s |
| T-AP-03 | **独占一台**，长跑 | CPU 满载数小时，不能与别的卡抢 |
| T-AP-04 | 任意 `code` | 数据构造 |
| T-AP-05 | `verify` 能力的 agent | 验收要独立于人 |
| T-AP-06 | `docs` 能力 | 文档 |

**并行上限**：01/02/04/06 四张可同时开；03 必须等 01+02，且训练期间不要在同一台机器上
再跑 02 的 benchmark（会互相抢 CPU 核，导致速度数字失真）。

## 六、风险与预案

| 风险 | 概率 | 预案 |
|---|---|---|
| 3MB 语料训不出能用的模型 | **高** | 降低目标为「语法合法 + 模仿见过的模式」；或引入 Light 标准库注释做预训练 |
| 200 tok/s 达不到（推理路径不够快） | 中 | 先做 KV cache + 单线程；再不行降到 d=128/L=4（564 tok/s） |
| 目标机拿不到 | 中 | V6 标 blocked，其余六条照常验收 |
| 01 卡词表设计反复 | 中 | 强制先出 4096 版，64K 版另开卡 |
| 03 训练期间 CPU 被抢 | 中 | 训练卡标 `exclusive`，dispatch 时跳过同机其他卡 |

## 七、明确不在 demo 范围内

- 64K 词表（另开卡）；
- 决策 token 的 RLVR 阶段（需 lightharness 环境）；
- 从真实日志导出的样本（导出器已交付，但修复样本拿不到，见 `docs/样本导出.md`）；
- 通用编程能力 —— 3MB 语料做不到，不要承诺。
