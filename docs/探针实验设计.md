# 探针实验设计：用 20% 训练成本回答「通不通」

> 对应原始方案 §7。本文补齐**可复现的实验协议**：数据怎么切、探针怎么训、指标怎么算、
> 什么情况算通过、不通过先调什么。

## 一、要回答的问题

只完成阶段一「词表共存」训练之后，决策 token 是否已经在共享表征中获得**有意义的编码**？
如果是，才值得投入剩下 80% 的训练量。

## 二、实验设置

| 项 | 取值 |
|---|---|
| 底座 | Qwen2.5-Coder-1.5B（备选：任一 1B 级底座，须记录 exact checkpoint） |
| 词表扩展 | 按[词表预算](词表预算.md)加入决策 token、验证 token、Light 高频语法组合 |
| 训练量 | 只跑阶段一（约完整课程的 20%） |
| 探针 | 冻结生成头与主干，只训一个线性分类器（< 1M 参数） |
| 探针输入 | 决策 token 位置的隐藏状态 |
| 探针输出 | 该决策点应选的选项（每决策点一个 softmax 头） |

## 三、三组对照

| 组 | 配置 | 用途 |
|---|---|---|
| **A 组（外挂）** | 独立轻量决策模型 + 原生成模型，由 lightharness 编排 | 决策准确率的**下限基准** |
| **B 组（纯生成）** | 不加决策 token，纯生成 + 后置 `light ai check` | 生成质量的**下限基准** |
| **C 组（探针）** | 阶段一词表共存训练 + 线性探针 | 待验证对象 |

## 四、指标定义（必须写明口径）

| 指标 | 定义 | 口径 |
|---|---|---|
| 探针准确率 | 探针在每个决策点上的 top-1 正确率，按决策点分别报，再报宏平均 | 只在**该决策点有正样本**的样本上算 |
| 一次通过率 | 单次生成无 error 级诊断的比例 | `map_diagnostics([]) == PASS` 即通过 |
| 结构合法率 | `parse_sequence()` 不抛错 **且** `validate()` 为空的比例 | 用本仓库 `lightprism` CLI 批量跑 |
| 决策密度 | 决策 token 数 / 序列项数 | **按段**；若要按子词算须另行声明 |
| 生成速度 | tokens/s，同一硬件同一 batch | 相对 B 组计算下降百分比 |

> 第 4 行的口径分歧是真实存在的：本仓库 `decision_density()` 按序列项计数，
> 训练侧按子词 token 计数。**报告里必须写清用的是哪一种**，否则 2% 的阈值不可比。

## 五、通过标准（四条同时满足）

1. 探针准确率（宏平均）**≥ A 组**独立决策模型；
2. 生成代码一次通过率 **≥ B 组**；
3. 结构合法率 **≥ 95%**；
4. 决策密度 ≤ 2% 且生成速度相对 B 组下降 ≤ 15%。

四条全中 → 推进阶段二。任一不中 → 先按第六节调参重跑阶段一。

## 六、不通过时的调整顺序（固定顺序，别乱试）

1. **词表预算分配**：决策 token 是多了还是少了？先看密度与准确率的相关性。
2. **阶段一数据配比**：决策 token 与代码 token 的共现比例是否过高/过低。
3. **嵌入初始化**：随机初始化 vs. 用选项名文本的 BPE 向量均值初始化。
4. **探针训练数据**：是否与决策点分布匹配（某些点样本过少会让宏平均被单点拖垮）。

## 七、警惕信号

| 现象 | 含义 | 处置 |
|---|---|---|
| 探针准确率高，但一次通过率显著下降 | 决策 token 正在挤占生成能力 | 降决策 token 密度/数量，查阶段一数据里决策样本占比 |
| 探针准确率≈随机 | 决策 token 没学到东西 | 查嵌入初始化与共现比例；可能训练量不足 |
| 结构合法率 < 95% | 模型没学会控制 token 的封闭语法 | 查 `<D:…>` 命名空间隔离；考虑加权 |
| 决策密度 > 2% | 「为了决策而决策」 | 阶段三 RL 惩罚项提前到阶段一做降采样 |

## 八、产出物

- `reports/探针实验_<日期>.md`：三组对照表 + 每个决策点的准确率 + 四条判定的逐条结论；
- `reports/探针实验_<日期>.json`：原始指标（供后续回归对比）；
- 若通过：一份「进入阶段二」的决定记录，写明底座 exact checkpoint 与词表版本号。

## 九、本仓库已可直接产出的部分

不需要 GPU 也能先跑通评估管线的这三段：

```bash
# 1) 结构合法率 + 决策密度（在模型输出的序列文件上跑）
PYTHONPATH=src python -m lightprism parse outputs/run-001.prism.txt --json

# 2) light ai check 结果 → 验证 token（一次通过率的分母/分子都从这里来）
PYTHONPATH=src python -m lightprism map-check check.json --json

# 3) 预算与 L0 原子性回归（防止词表改动悄悄破坏底约束）
PYTHONPATH=src python -m lightprism budget --json
PYTHONPATH=src python -m lightprism l0 tokens.json --json
```
