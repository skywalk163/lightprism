# 训练与推理骨架

> 范围：`src/lightprism/{model,model_cfg,tokenizer,data,train,infer,probe}.py`。
> **这是一条能跑的完整管线，不是能产出 1B 模型的训练脚本。** 两者差别写在 §6。

## 一、装依赖

```bash
pip install -e ".[train]"     # torch >= 2.2
```

不装也能跑全部纯标准库测试（`tests/test_model.py` 用 `importorskip` 整体跳过）。

## 二、五条命令跑完一轮

```bash
# 1) 校验模型配置并报参数量（不需要 torch）
PYTHONPATH=src python -m lightprism config configs/1b.json
#   → 参数量 950M（950,111,232），非嵌入 849,447,936

# 2) 训练（阶段一 · 词表共存）
PYTHONPATH=src python -m lightprism.train \
    --data data/samples.jsonl --steps 4 --seq-len 128 --batch-size 3 \
    --log-every 1 --out-dir outputs/smoke

# 3) 生成（带结构约束）
PYTHONPATH=src python - <<'PY'
from lightprism.infer import load_generator, GenConfig
gen = load_generator("outputs/smoke/model.pt", GenConfig(max_new_tokens=32))
out = gen.generate("检查磁盘使用率", decisions={"EDIT": "FR"})
print(out["decisions"], out["structure_ok"], out["seq_text"][:60])
PY

# 4) 探针（阶段一结束后的判定实验）
PYTHONPATH=src python - <<'PY'
from lightprism.data import load_jsonl
from lightprism.infer import load_generator
from lightprism.probe import train_probe, PassCriteria, judge
samples, _ = load_jsonl("data/samples.jsonl")
gen = load_generator("outputs/smoke/model.pt")
res = train_probe("outputs/smoke/model.pt", samples, gen.tokenizer)
print(res.as_dict()); print(judge(PassCriteria(**res.as_dict())))
PY
```

## 三、各模块职责

| 模块 | 职责 | 是否依赖 torch |
|---|---|---|
| `model_cfg.py` | `PrismConfig` + 参数量公式 | ❌ |
| `model.py` | decoder-only 主体（pre-norm + QK-Norm + RoPE + SwiGLU） | ✅ |
| `tokenizer.py` | 把底座词表与 LightPrism 控制 token 拼成 64K 词表；结构状态机 | ❌ |
| `data.py` | 样本 schema、JSONL 往返、定长批次、id 口径统计 | ❌ |
| `train.py` | 阶段一/二的训练循环、余弦退火、checkpoint | ✅ |
| `infer.py` | 约束解码、生成后置复核挂点 | ✅ |
| `probe.py` | 线性探针 + 四条通过标准判定 | ✅ |

纯标准库的四个模块（`model_cfg` / `tokenizer` / `data` / 前四个 CLI 子命令）被 `lightprism config`、
`lightprism parse` 等命令依赖，**CI 里必须能在没装 torch 的机器上跑通**。第一版把 `PrismConfig`
放在 `model.py` 里，导致 CLI 一执行就 import torch，已拆开。

## 四、关键设计决定

### 4.1 控制 token 占词表末尾的连续 id 区间

`<TASK>` / `</TASK>` / `<CODE>` / `</CODE>` → 全部 19 个决策 token → 全部 8 个验证 token，
共 31 个 id，落在 `[base_vocab_size, base_vocab_size+31)`。好处：

- 训练侧判断 token 类型只需比较区间，不用查表；
- 损失加权、梯度监控、探针取样都按区间过滤；
- 区间有空洞会在 `ControlTokenLayout.finalize()` 里直接报错。

### 4.2 约束解码用「结构状态机」，不是只看上一个 token

只看 `last_id` 完全拦不住未经训练的小模型：实测它会连续吐几十个 `</TASK>`，或连续几十个
`<D:EDIT=FR>`。`PrismTokenizer.allowed_next(history)` 按完整历史重构状态，再从状态推白名单：

| 状态 | 允许的下一个控制 token |
|---|---|
| 还没有 `<TASK>` | `<TASK>` |
| `<TASK>` 里 | `</TASK>` |
| `</TASK>` / `<D:…>` 之后 | 同一步**未用过**的决策点 + `<CODE>` |
| `<CODE>` 里 | `</CODE>` |
| `</CODE>` 之后 | `<V:…>` 之一 |
| `<V:…>` 之后 | 新一轮决策点 + `<CODE>` |

自由文本位置返回 `None`（不约束）——硬约束会写错，因为代码体和任务体都允许任意字符。

### 4.3 生成结果区分「模型吐错」与「我们截断」

`generate()` 返回 `structure_ok` / `truncated` / `counts_toward_structure_rate` 三个字段。
探针实验的结构合法率**只能用第三个**统计：生成到 `max_new_tokens` 上限被切断时，尾部裸露文本
是截断造成的，不该记在模型头上（骨架阶段每一条都会命中这个情况，不区分就会得到 0% 的假数字）。

### 4.4 checkpoint 必须存底座词表本体

第一版只存了 `base_vocab_size`，恢复时用 `<padNNN>` 占位凑数，解码出来全是占位符，
把结构合法率误判成 0。现在存 `base_vocab` 全量列表，恢复时校验大小一致，缺失就明确报错。

## 五、阶段配置差异

| | 阶段一 `coexist` | 阶段二 `cooperate` | 阶段三 `rlvr` |
|---|---|---|---|
| 数据形态 | 三类 token 随机交错 | 严格决策→代码→验证 | 同左 + 奖励 |
| 控制 token 损失权重 | 1.0（不加权） | 2.0 | 2.0 |
| 本仓状态 | ✅ 可跑 | ✅ 可跑 | ❌ 抛 `NotImplementedError` |

阶段三不做是**故意的**：RLVR 要真实执行 `light ai check` 并回传奖励，那是 lightharness 侧的能力。

## 六、放大到真实 1B 训练前必须补

`train.py` 底部有同名常量 `SCALE_UP_REQUIRED`，改代码时请同步：

1. **真实 BPE 词表**：当前用 `CharTokenizer` 顶替（逐字编码），仅够验证管线形状。
2. **数据并行 / 梯度累积**：当前 `grad_accum` 是串行累加，没有 all-reduce。
3. **按 token 类型分组的梯度范数**：方案 §8.6 要求分别看决策 token 与代码 token 的梯度，
   当前只有全局范数。
4. **bf16 autocast + 激活重计算**：1B 在 CPU 上跑不动。
5. **断点续训**：当前只存权重，不存优化器状态与学习率调度位置。
6. **阶段二的严格交错数据与 loss 掩码**：当前只调了控制 token 权重，没有对「同一位置多选」做掩码。

## 七、已知限制（明确写在这里，别让下一个人猜）

- 用 3 条样本训出来的模型只会重复高频片段，**任何生成样例都不是能力证明**；
- 探针在样本不足时用训练集自评，`eval_split` 字段会标注 `train(...)`，
  且这种点**不计入**宏平均；
- `judge()` 遇到缺失指标返回 `incomplete`，不会因为缺数据就判通过。
