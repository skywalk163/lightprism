# 三远端与发布

## 一、远端清单

| 远端名 | 地址 | 角色 |
|---|---|---|
| `origin` | `http://192.168.1.5:3000/skywalk/lightprism.git`（自托管 Gitea） | 内网权威源，CI 门禁 |
| `github` | `git@github.com:skywalk163/lightprism.git` | 公开镜像 + GitHub Actions |
| `gitcode` | `git@gitcode.com:skywalk163/lightprism.git` | 国内公开镜像 |

三个远端都是 **public**、默认分支 `main`、`auto_init=false`（首推即建分支，没有空提交残留）。

## 二、推送与复核

```sh
sh scripts/push-all.sh          # 推 main 并逐远端 ls-remote 比对
```

**不要用 `git push <remote> | tail` 当复核**：管道里 `$?` 拿到的是 `tail` 的返回码，
push 即使 rc=128 也会显示"成功"（lightharness `docs/国庆7天/Day12_多远端收敛.md` §8.2 有反跑证据）。
`scripts/push-all.sh` 的复核方式是逐远端 `git ls-remote` 比对 SHA，失败即 exit 1。

## 三、打 tag

```sh
git tag -a vX.Y.Z -m "..." && git push origin vX.Y.Z && git push github vX.Y.Z && git push gitcode vX.Y.Z
```

tag 必须打在**已推送并复核过**的 commit 上；本地改 tag 后三远端都要 `-f` 更新，否则
`git ls-remote <remote> refs/tags/vX.Y.Z` 会指向旧 commit。
