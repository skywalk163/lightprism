## 先看结论

## 诚实边界（务必随报告一起读）

- 真实决策标签只覆盖 1/7 个决策点（['EDIT']）
- 真实一次通过率需 light ai check --json --run，OpenI 无光明解释器，本环境不可测；光明代码类样本亦不并入 JSON 代理（记为口径限制，不单独占一条判据）
- A/B 组是本次实验内的消融对照，不是方案书里已部署的外部系统
- C/B 组同 epoch、同 batch-size，但 C 组每条序列多出决策/验证 token；比较的是结果指标，不是等 token 预算下的严格对照
- 判据 ②③ 要求 ≥30 条评估样本，且 ② 要求差距 ≥3 条；不足记 unknown
- 探针主特征取决策 token 前一位置（pos-1）；自身位置的探针只作泄漏对照，不参与判据（v1 误用自身位置，导致 C 组与打乱组探针都是 1.000）
- v3 门禁命中：决策点只覆盖 1/7 个（['EDIT']）；探针 test 样本 9 条 < 30；train/test 模板簇重合 27 个（A 组可能是记忆而非泛化）。①（探针）与差距不足的 ② 因此不可测；③④ 不依赖决策标签，仍为有效测量（可能 pass 也可能 fail）。综合结论「方案通不通」无判别力，整体记 incomplete，不升级为 fail/pass
