## 1. 结论摘要

OpenI V100 两轮 + A 组 512 预算的实测结论是**判据卡在数据，不在算力**：
`verdict=incomplete`，三条门禁把 ①②③ 全锁成 unknown。根因是
`data/runtime/decisions.jsonl` 里的 **241 条真实决策从未进入训练**——
`build_ids(decision_policy=real)` 只认 `meta.category=="decision"` 且答案 JSON 含
`decision∈{FR,RW,PATCH}`，全库只能产出 36 个 `<D:EDIT=*>`；`load_samples()` 也只读
`json_tasks / code_tasks / err_tasks` 三个键。

本卡把这条链路接通，并让 v3 门禁的三条 blocker 全部消失（覆盖 7/7、test 决策行
≥30、train/test 模板零重合），使后续复跑具备判别力。**门禁解除 ≠ 判据通过**。

## 3. 接线实现

### 3.1 payload（`train_openi.py`、`scripts/embed_payload.py`）

* 新增 `decisions` 键：`_load_payload()` 的 `--data-dir` 分支读 `decisions.jsonl`
  （缺失即空串，不报错）；内嵌分支从重建后的 `_PAYLOAD_B64` 解压得到。
* `scripts/embed_payload.py` 从 `data/unified/decisions.jsonl` 打包，并写入
  `meta.decisions_sha256`；`--check` 现在比对 `decisions`，内嵌缺该键会报
  「不一致」而不是静默通过。
* 旧 payload（无 `decisions` 键）`setdefault("decisions", "")` 后行为完全不变：
  不报错、不产生决策样本、判据口径零影响。
* 内嵌 payload 已重建：压缩体积 33,728 → 81,137 bytes（+47 KB，241 条决策）。

### 3.2 样本（`load_samples()`）

每条决策日志转成一个样本：

```
task                 = task_text
steps[0].code        = source
steps[0].validation  = validation_code
steps[0].decisions   = decisions（原始 6~7 点）
meta.template        = template_id
_category            = "runtime_decision"
```

字段缺失、`decisions` 空、验证码未在词表登记 → 立即 `ValueError`，
**绝不静默丢行**。三种拒绝路径都有单测覆盖。

### 3.3 标签（`build_ids()` real 策略）

* 样本自带 `steps[0].decisions` 时**原样注入每个点**（经 §4 限量后的
  `_kept_decisions`），不再看 `meta.category`。
* 注入前逐点校验：`point ∈ Vocab.point_token_ids` 且
  `<D:{point}={option}> ∈ Vocab.decisions`，非法直接报错。
* 没有自带决策字段时退回旧逻辑（旧库 decision 类从答案 JSON 取 EDIT），
  老样本行为不变。

### 3.4 密度上限与确定性限量（`decision_budget()`）

全量注入 241 × (6~7) = **1456 个决策 token**；纯决策样本序列密度约 0.078，
混入老样本后 group-split train 子集仍有 0.0184。为留出安全余量，按
**sha256 派生**的确定性轮转给每条样本只保留 1 个点：

```
h = sha256(task + "\0" + code)
主点 = argmin sha256(str(h) + "\0" + point)   # 可复现，不依赖 RNG
```

稀有点特例：FIX 只在 10 条重试记录、集中在 3 个模板簇，轮转可能一条都不选或
全落同一侧。让**每条含 FIX 的样本都保留 FIX 点**（真实日志里它本就是该条决策
的一部分，不是伪造），配合 §3.5 的簇级交替，train/test 两侧各有 FIX 正样本。

取舍结果（内嵌 payload，group-split，seed=0）：

| 决策点 | CTX | EDIT | FIX | NEXT | PLAN | RETRY | SAFE | 合计 |
|---|---|---|---|---|---|---|---|---|
| 保留条数 | 31 | 38 | 10 | 27 | 40 | 40 | 55 | **241** |

训练序列决策密度 **0.003858**（上限 0.02），`DENSITY_MAX` 未改。

### 3.5 构造性零重合（`stratified_split()` group-split）

* 原有 `template_key`（类别 + 归一化 task 文本）已保证同模板变体整体进同一 split，
  overlap 结构上恒 0。本卡保持该机制，不靠换 seed。
* 新增**簇级稀有点交替**：收集含 FIX 的 3 个模板簇，整簇摘出后按
  `template_key` 排序、奇偶交替钉到 train / test。迁移以簇为单位（绝不拆分），
  因此 overlap 仍为 0，且 train/test 都有 FIX 正样本、样本总数守恒。
  实测 seed = 0/1/2/7/42 全部满足（见单测参数化用例）。

### 3.6 门禁（`judge()`，阈值未改）

门禁的三条 blocker 由数据侧满足，judge 代码**一行未动**：

* `points_with_test_labels = 7` → 探针 7 点都有 test 样本；
* `n_test_decision_rows = 78 ≥ 30`（`MIN_PROBE_TEST_ROWS` 未改）；
* `train_test_template_overlap = 0`（构造性）；
* 附加 ERR 门禁：`has_err_validation = true`。

`gated=false` 后，① 探针准确率、② 一次通过率、③ 结构合法率、④ 密度/速度
**按真实数值如实判定**。单测构造 gate 已解除但 ③=0.5385 的场景，断言
③ 仍为 `fail`、`verdict=fail`——证明解除门禁没有吞掉判据结果。
