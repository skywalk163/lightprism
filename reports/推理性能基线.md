# 推理性能基线（T-0331，demo-3m）

## 1. 被测配置

| 项 | 值 |
|---:|---:|
| 配置档 | `configs/demo-3m.json` |
| 维度 d / 层数 L / 头数 H | 192 / 6 / 6（head_dim=32） |
| 词表 V / 最大序列 | 4096 / 512 |
| FFN 隐层 | 512（SwiGLU，`ffn_mult=4.0`） |
| QK-Norm / 权重绑定 | 开启 / 绑定嵌入（tie_embedding） |
| 参数量 | 3,443,520（非嵌入 2,657,088），约 3.44M |

## 2. 测试机环境

| 项 | 值 |
|---:|---:|
| 系统 | FreeBSD 15.1-RELEASE-p1 amd64 |
| CPU | Intel Xeon E5-2643 v2 @ 3.50GHz，12 核（Ivy Bridge EP，**无 AVX2**） |
| 内存 | 约 64 GB |
| Python / torch | 3.12.13 / 2.12.1a0（BLAS=open，CPU capability=DEFAULT，OpenMP） |

## 3. 基准口径（写死在 `scripts/bench.py`，不接受命令行覆盖）

- 单线程：`torch.set_num_threads(1)`；贪心 argmax 解码；
- prompt 长度 32，prefill 耗时**不计入** decode 吞吐；
- 丢弃前 10 个 decode 步作为预热，吞吐只在剩余 token 上统计；
- 权重随机初始化（只测推理路径速度，不测生成质量）；
- 多线程对比另走 `--mode multi`，单独报告，不作为验收口径。

## 4. 实测结果

### 4.1 单线程（验收口径）

| 生成 token | 计时 token | 速度（多次跑次区间） | 单 token 耗时 | 峰值 RSS |
|---:|---:|---:|---:|---:|
| 100（验收命令） | 90 | **74.0–96.5 tok/s** | 10.36–13.51 ms | 283.0–283.1 MB |
| 200 | 190 | 80.4–85.6 tok/s | 11.68–12.43 ms | 279.9–283.0 MB |

> 长序列平均更慢，是 KV 缓存长度增长后注意力取历史 K/V 的线性开销所致；不同跑次波动较大，
> 单 token 中位数落在 **10.4–13.5 ms**，整体约 **74–97 tok/s**。

### 4.2 多线程（12 线程，仅对比，不作验收）

| 生成 token | 线程 | 速度 | 单 token 耗时 | 峰值 RSS |
|---:|---:|---:|---:|---:|
| 200 | 12 | 7.7 tok/s | 130.680 ms | 286.4 MB |

多线程在 decode 阶段反而远慢于单线程：小张量下 OpenMP fork/join 的同步开销压倒并行收益，
与任务卡「多线程在 decode 阶段往往因同步开销反而更慢，要实测」的预判一致。**以单线程数字为准。**

## 5. 单步耗时拆解（单线程，decode 中位数）

逐层手动插桩（`t=1`，缓存长度约 42），单个 decode 步各段中位耗时：

| 段 | 中位耗时 |
|---:|---:|
| 嵌入 lookup | 0.032 ms |
| 单层 Block（6 层合计为主导） | 2.0–2.4 ms / 层 |
| └ norm1 | 0.099 ms |
| └ QKV 投影 | 0.181 ms |
| └ Q/K-Norm（两个） | 0.235 ms |
| └ RoPE（Q+K） | ≈0.436 ms |
| └ K/V 拼缓存 | 0.026 ms |
| └ SDPA（decode，T=1） | 0.078 ms |
| └ 输出投影 | 0.080 ms |
| └ norm2 | 0.147 ms |
| └ FFN（w1·silu·w3·w2） | 0.369 ms |
| 末尾 norm_f + lm_head | 0.828 ms（其中 lm_head GEMM 0.547 ms） |

- 纯矩阵乘（所有 Linear，去掉归一化/RoPE/注意力/激活）估算下限约 **2.7 ms/步**；
- 同形状裸矩阵乘对照：torch `mm` 0.088 ms，numpy `mm` 0.038 ms，本机 torch CPU 后端
  比 numpy 同形状慢约 2.3 倍。

## 6. 与合成基准的差异解释

任务卡合成基准表（按 FLOP / 带宽推算，标注 12 线程）给出本档 d=192 / FFN 512 / L=6：
**3.53 ms/token，约 283 tok/s**；完成标准要求本机单线程 ≥250 tok/s。

**实测单线程 10.4–13.5 ms/token（约 74–97 tok/s），未达到 ≥250 tok/s。** 差异来源：

1. **合成表是规模上限估算，不是本实现端到端实测。** 端到端每个 token 要经过 6 层 ×
   （QKV / 投影 / 双 RMSNorm / RoPE / SDPA / SwiGLU）+ 末尾归一化与输出头，算子数量多，
   小张量上固定调度开销被放大。
2. **本机 CPU 无 AVX2**（Ivy Bridge EP），torch 构建 CPU capability=DEFAULT、BLAS=open
   （OpenBLAS），未走 MKL / oneDNN 高向量化路径；裸矩阵乘即比 numpy 慢约 2.3 倍。
3. **decode 张量极小**（T=1，head_dim=32），归一化归约、RoPE 视图切片/拼接、非连续
   视图拷贝等小算子的固定开销占比高；矩阵乘本身只占约 2.7 ms，其余为算子调度与拷贝。
4. **多线程无增益**：12 线程实测 7.7 tok/s（130.7 ms），同步开销主导，不能靠加线程提速。

## 7. 结论与遗留风险

- **正确性已达标**：KV cache 预填 + 逐步 decode 的 logits 与全量重算在 `atol/rtol=1e-4` 内一致
  （`tests/test_kv_cache.py` 4 项）；既有 `tests/test_model.py` 28 项回归全部通过。
- **吞吐未达标**：单线程约 74–97 tok/s，低于 ≥250 tok/s 目标。进一步提速需要更换带
  MKL / oneDNN / AVX2 优化的 torch 构建，或对小算子做融合内核；这些超出本卡允许的改动
  路径（`model.py` / `model_cfg.py` / `infer.py` / `configs` / `bench.py` / 测试 / 报告），
  且按禁止条款未引入 transformers / vllm / numpy 等重依赖。
- KV cache 已生效：decode 每步只喂 1 个 token、缓存逐层追加；若退回全量重算，序列长度上
  会按 O(T²) 退化。
