## 一、问题是什么

## 三、词表：两个 token 怎么进预算

| token | 64K id | 4096 demo id | 来源 |
|---|---:|---:|---|
| `<PY>` | 64000 | 2900 | `reserved` 槽位头部第 1 个 id |
| `<LIGHT>` | 64001 | 2901 | `reserved` 槽位头部第 2 个 id |

* `reserved` 仍按 **1536** 计入总额，只是内部切出前 2 个 id；八行预算与 65536 总和
  一行未改，`VocabBudget.problems(TokenSpace()) == []`。
* id 由 `slot_offsets()["reserved"]` 推导，`SEGMENT_TOKEN_IDS` 是唯一事实源；
  测试直接钉死 64000/64001，重排预算表会红。
* 段标记不占 `decision` / `validation` 额度：19 个决策 token、9 个验证 token 的
  id 区间与 64000/64001 不相交（`test_segment_tokens_do_not_consume_decision_or_validation_quota`）。
* **为什么是 2 个不是 4 个**：卡面允许“等价定长段标记”。采用 starter-only：
  `<PY>` 段到 `<LIGHT>` 或 `<V:…>` 结束，`<LIGHT>` 段到 `<V:…>` 或序列末尾结束。
  段边界由下一个结构 token 唯一确定，不需要两个闭合 token；解析器仍接受显式
  `</PY>` / `</LIGHT>`（向前兼容），但训练渲染器不产出。

### 方案 b：旧 checkpoint 兼容

demo 4096 词表选择方案 (b)（复用 reserved/旧 UNK-PAD 槽位），没有把嵌入扩到 4098：

* 旧 2900 条 token 的 id `0..2899` 与语义完全不变；
* 新 token 追加在验证 token 之后：`<PY>=2900`、`<LIGHT>=2901`；
* `UNK=2902`、`PAD=2903`，`DemoVocab.vocab_size` 仍为 **4096**。

旧 checkpoint 的 `embed.weight` 仍是 4096 行，可 `strict=True` 加载；旧序列只用到
`≤2899` 的有效 token，PAD 不作有效目标，UNK 只覆盖 <1% 未登录字符，因此把旧的
2900/2901（UNK/PAD）解释成段标记对旧序列影响有界。证据不是口头保证：
`tests/test_demo_vocab.py::test_old_checkpoint_state_dict_loads_with_new_vocab`
真的构造旧 state_dict 并 strict 加载进新词表模型。

## 四、序列格式与“训练/推理同一函数”

训练序列（`markers` 模式）：

```
<FORMAT>translate</FORMAT>
<TASK>把 Python 翻译成光明</TASK>
<PY>
x = 1
print(x)
<LIGHT>
设 x 为 1。
印 x。
<V:PASS>
```

推理 prompt 就是同一序列去掉 `<LIGHT>` 之后的目标段。实现上只有一个核心
`_render_translation_core(task, py, light, mode, include_target)`：

* `render_training_translation(..., include_target=True)` —— 训练；
* `render_inference_translation(..., include_target=False)` —— 推理；
* `test_translation_training_and_inference_share_one_renderer` 对两种模式都断言
  `training.startswith(prompt)`；改坏一侧就红。

## 七、判读：只能写 inconclusive

* 3.4M 参数 + 200 步，远低于 T-0347 的 3000 步；两组生成都还没有形成稳定翻译能力，
  结构合法率接近 0 是**训练预算不足**的预期结果，不是段标记的失败证据。
* val loss / CE 只能说明“两种格式都能被模型拟合”，不能说明哪种格式更能治混淆；
  CE 的分母 token 数因格式不同而不同（markers 多两个控制 token），只作方向性参考。
  两组 val loss 差 0.0006（baseline 4.44012 / markers 4.43952），等价于打平；
  翻译 CE 反而是 baseline 低 0.087（3.74018 / 3.82678）。
* **段边界命中率是本次最有信息量的数**：baseline 13/16、top-5 16/16；markers
  0/16、top-5 0/16。逐样本看，markers 模型在 `<PY>` 段尾预测的是换行而不是
  `<LIGHT>`；这是“没学会”，不是“学反了”。最可能的解释是**曝光量**：`<CODE>`
  在 json/code/corpus/err 所有序列里天天出现，`<LIGHT>` 只在 893 条 pair 里出现；
  同 200 步、同 repeat 下，新标记拿到的梯度少一个量级。这个 confound 是格式改动
  本身带来的，在“除格式外完全同参”的卡面约束下不能靠调 `translate_repeat` 消除。
* 因此证据等级写 **`inconclusive`**：本卡交付的是“机制 + 可复现对照器械 + 可测的
  兼容性”，不是“新标记更好/更差”的结论。要下结论，下一步应做**曝光对齐实验**：
  把 `translate_repeat` 提高到与 `<CODE>` 曝光同量级（或加入 light_only 的
  `<LIGHT>` 序列），再与 T-0347 同量级（≥3000 步）重跑，并扩大翻译 held-out。
