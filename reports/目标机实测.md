## 5. 判定：是否 ≥200 → **否，V6 未通过**

1. **硬指标未放宽**：卡面 200 tok/s 原样保留，3 次全部不达标，最好一次 103.12 仅为目标的 51.6%。
2. **阈值断言给出同样结论**：用 T-0340 版 bench.py 跑卡面原样命令，输出 `未达阈值: 102.5 < 200 tok/s`、exit 1；附加对照的 JSON 里 `threshold.passed=false`。这是**真实的性能判定**，不是平台假失败。
3. **按计划可提前判死**：`docs/Demo验收报告.md` §7.3 写「看是否单调更快；**若 AVX2 机器仍 < 200，则 V6 基本可以提前判死**」。本机 AVX2 实测 ~102，满足该条件。
4. **为什么 AVX2 没补上差距**（与 T-0340 的物理分析一致）：T-0340 在 Ivy Bridge 上测得纯 GEMM 地板 **3.21 ms/步**、非 GEMM 开销约 **6.3 ms/步**；200 tok/s 要求整步 ≤5.0 ms，留给小算子/调度的预算只有 1.79 ms。瓶颈在**小算子与 Python 层调度**，不是矩阵乘宽度，因此 AVX2 的向量宽度优势补不上 2× 缺口；本机 2.10 GHz 也低于验收机的 3.50 GHz，进一步抵消收益。
5. **附加对照，排除「main 没合入提速」这个借口**：把 `origin/task/T-0340`（`edfbbfb`，含 RoPE 余弦表缓存优化）整棵快照导出到临时目录，用其自己的 `model.py` + bench.py 同口径跑 → **99.83 tok/s**、`threshold.passed=false`、`未达阈值: 99.8 < 200 tok/s`、exit 1。连提速版产物也不达标，且并未更快。**这是非 main 口径的旁证，不计入 3 次实测。**
6. **状态表述**：V6 从「`blocked`（无机器）」变为「**真机实测完成、但实测未通过**」。卡面「只有真机实测完成后才 unblock → done」是针对「拿不到机器」的对称条件，不能把「测了但不达标」当 done——那等于宣称「8GB 5 代酷睿 ≥200 tok/s」这个承诺已兑现。**worker 不 unblock、不 declare done**，请 controller 裁定（判死 / 降级承诺 / 继续优化）。

## 附录 B：Windows `resource` 垫片（只影响内存字段）

`%TEMP%\lpv6\shim\sitecustomize.py`，通过 `PYTHONPATH` 加载，仅在本次测量进程中生效：

```python
import sys, types, os
if os.name == "nt" and "resource" not in sys.modules:
    import ctypes
    from ctypes import wintypes
    class _PMC(ctypes.Structure):
        _fields_ = [("cb", wintypes.DWORD), ("PageFaultCount", wintypes.DWORD),
                    ("PeakWorkingSetSize", ctypes.c_size_t), ("WorkingSetSize", ctypes.c_size_t),
                    ("QuotaPeakPagedPoolUsage", ctypes.c_size_t), ("QuotaPagedPoolUsage", ctypes.c_size_t),
                    ("QuotaPeakNonPagedPoolUsage", ctypes.c_size_t), ("QuotaNonPagedPoolUsage", ctypes.c_size_t),
                    ("PagefileUsage", ctypes.c_size_t), ("PeakPagefileUsage", ctypes.c_size_t)]
    _psapi = ctypes.windll.psapi
    def _getrusage(who):
        pmc = _PMC(); pmc.cb = ctypes.sizeof(_PMC)
        ok = _psapi.GetProcessMemoryInfo(ctypes.windll.kernel32.GetCurrentProcess(),
                                         ctypes.byref(pmc), pmc.cb)
        r = types.SimpleNamespace(ru_maxrss=(pmc.PeakWorkingSetSize // 1024) if ok else 0)
        return r                       # ru_maxrss 单位 KB；bench.py /1024 得 MB
    _m = types.ModuleType("resource")
    _m.RUSAGE_SELF, _m.RUSAGE_CHILDREN, _m.getrusage = 0, -1, _getrusage
    sys.modules["resource"] = _m
```

`bench.py` 中 `resource` 唯一出现位置是 `peak_rss_mb()`；计时在 `run_decode()` 用 `time.perf_counter()`，判据不受垫片影响。实测 `peak_rss_mb` ≈ 201.6–202.1 MB，与 .88 上 `ru_maxrss` 口径（287.7 MB，不同的 torch 构建/平台）量级一致，读数合理。
