CPUID `Family 6 Model 61 (0x3D)` = **Broadwell-U，第 5 代酷睿**；`IsProcessorFeaturePresent(PF_AVX2_INSTRUCTIONS_AVAILABLE=40) = True`。**硬件层面这台机器确实符合「真 5 代酷睿 / 有 AVX2」**——这一点与 T-0334「全集群没有 Broadwell 机器」的旧结论冲突，是本卡核查出的新事实，已同步 controller。

**但本次不把它当作「目标机」，理由五条：**

1. **红线明令「不许拿本机数字冒充目标机」。** 它是本次执行/验收所在的机器，正是卡面语义里的「本机」角色；V6 的全部意义是**换一台机器**复现「8GB 内存 5 代酷睿 ≥200 tok/s」这个部署承诺。在同一台机器上自测自证，不构成目标机实测。
2. **卡面取证口径是 POSIX，本机给不出。** 卡面要求 `sysctl -a | grep avx2` 或 `lscpu` / `/proc/cpuinfo` 的 **CPU flags 文本**；Windows 三者皆无。Win32 的 `IsProcessorFeaturePresent(40)` 是 API 特性位，不是 CPU flags 原始输出，不能替代验收要求的「目标机 CPU flags（含 avx2）」。
3. **本机跑不了 bench.py，且不许改口径补救。** `scripts/bench.py:29` 是 `import resource`（POSIX-only），Windows 下原样执行直接失败（见 §3.1）；本机 Python 3.13.14 与 3.12 均未装 torch（`torch spec: None`，`resource spec: None`，pyproject 把 torch 放在 optional extra）。为了在 Windows 跑起来而动 bench.py = 改口径，被红线禁止。
4. **存在一台 Broadwell ≠ 目标机到位。** 「目标机」是性能承诺指向的部署机，需有明确的机器身份、验收归属与可复现的取证环境。执行机不能自封为目标机；是否把这台机器认定为 V6 目标机，须由 controller / 业主裁定并改卡，不是 worker 可以单方面决定的。
5. 交办契约已把「不许拿本机数字冒充目标机」列为首要前提，且给出「失败时写 summary 并回 hive_submit，不要硬凑」的处置路径。
