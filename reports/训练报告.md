## 一、结论（先看这一段）

| 判据 | 要求 | 实测 | 结论 |
|---|---|---:|---|
| 模型规模 | 约 3.4M 参数 | **3,443,520**（non-embedding 2,657,088） | ✅ |
| 词表对齐 | 4096 词表，控制区间连续 | vocab_size=4096，控制 id [2868,2900)，UNK=2900，pad=2901 | ✅ |
| 训练闭环 | 50 步跑通，落 checkpoint | **50 步完成**，`model.pt` 13.8 MB，`train_log.json` 落盘 | ✅ |
| smoke 加载 | checkpoint 可还原、生成不崩 | 32 token 贪心生成退出码 0，id 全部在 [0,4096) | ✅（管线通） |
| 单元测试 | 词表/切分/打包/规模/端到端 | **8 passed**（FreeBSD 15.1 / torch 2.12.1a0 / pytest 8.4.2） | ✅ |
| 生成语法合法率 | 能生成语法合法代码 | **0 / 8 条含结构标记，生成退化为空格重复** | ❌ 未达到（见 §五） |

**一句话结论**：训练管线、数据装配、模型规模、checkpoint 持久化与 smoke 加载全部跑通；
但 50 步 / 3.4M 小模型在 2.2 MB 语料上尚未学到有效语法结构，生成退化为高频空格 token，
**不具备生成语法合法代码的能力**。这是受步数与数据规模限制的预期内结果，未做任何凑数。

### 2.2 数据装配（可复现，种子固定）

两路训练语料，均来自仓内既有产物，不调用模型批量生成：

1. **代码语料（自回归 LM）**：`data/corpus/index.jsonl` 中 `kept=true` 的 **392** 个上游
   `.light` 文件，合计 **2,297,455 字节（≈2.19 MB）**。按**文件**做 5% 验证集切分，
   种子 `20261112` → train **372** 文件 / val **20** 文件。
2. **SFT 任务集**：T-0333 的 `json_tasks.jsonl`（300，6 类各 50）+ `code_tasks.jsonl`（63），
   合计 **363** 条，渲染成 `<FORMAT>…</FORMAT> <TASK>…</TASK> <CODE>…</CODE> <V:PASS>` 序列，
   全部进训练集；验证集只用代码语料。

分词为词表清单上的**贪心最长匹配**（多字 token 按长度降序），未覆盖字符落 UNK 槽位。
序列首尾相接切成 `seq_len=512` 定长块，残块丢弃；targets 错位一位，pad 位权重 0。

## 五、生成质量与语法合法率（如实记录）

### 5.1 样例

用 SFT 前 8 条任务文本做 prompt，贪心生成 64 token，结果**全部退化为空格（id 1923）重复**：

| 任务（截断） | 生成文本 | 去重 token 数 | 含 `<TASK>` | 含 `<CODE>` | 含 `<V:` |

| 已知目录内容为：model.py 8650 字节… | 64 个空格 | 1 | 否 | 否 | 否 |
| 已知目录内容为：vocab.py 8313 字节… | 64 个空格 | 1 | 否 | 否 | 否 |
| 已知目录内容为：设计方案.md 7005 字节… | 64 个空格 | 1 | 否 | 否 | 否 |
| 已知目录内容为：300m.json 337 字节… | 64 个空格 | 1 | 否 | 否 | 否 |
| 已知目录内容为：T-0332_训练demo模型… | 64 个空格 | 1 | 否 | 否 | 否 |

| 已知目录内容为：sequence.py 8334… | 64 个空格 | 1 | 否 | 否 | 否 |

### 5.2 合法率口径与实测

- **结构合法率**（含成对 `<TASK>/<CODE>/<V:…>` 标记）：**0 / 8 = 0%**。
- **词汇多样性**：8 条 × 64 token 共 512 token，全程只出现 1 个不同 token（空格），
  无任何代码片段或结构标记。
- 退化原因分析：训练流中空格占比 **30.69%**（331,854 / 1,081,448 token），是最高频 token；
  50 步、3.4M 参数、CPU 训练下模型只学到了最高频的边缘分布，未形成上下文条件化，
  argmax 被空格持续占据。这与 loss 仍在 5.5–6.0（远未收敛）一致。

### 5.3 诚实边界

- 本 checkpoint 定位是**管线 demo**：验证词表、模型核、数据装配、训练闭环、持久化与推理加载
  整条链路可跑通；**不承诺生成语义正确或语法完整的程序**。
- 要产出可生成合法代码的模型，需要显著更多步数 / 更大 batch / 更多语料，或在本 demo 基础上
  做长程 SFT 与结构约束解码；这些超出 T-0332 的 50 步 demo 范围，未在本卡内实现。
