## 三、词表构建

### 3.1 分层条数与建议值偏差理由

| 层 | 卡面建议 | 实测 | 说明 |
|---|---:|---:|---|
| `l0` | 44 | **44** | `LIGHT_L0_CORE`，一字一 token，硬约束，不可调 |
| `syntax` | 512 | **1697** | 通用单字（按频次累计覆盖 99.8%）+ 高频 2—4 字组合 |
| `stdlib` | 768 | **182** | 真实可提取的模块名/导入名，只有 182 个，**不硬凑** |
| `ascii` | 2048 | **945** | 95 个可打印 ASCII 单字符 + 850 个高频标识符片段 |
| `control` | 31 | **32** | 4 结构 + 19 决策 + **9** 验证（见 3.3） |
| 合计 / 余量 | 3403 / 693 | **2900 / 1196 (29.20%)** | 余量比建议更大 |

偏差理由（卡面允许「可微调但要写理由」）：

1. **`syntax` 扩容到 1697**：卡面同时要求「UNK 率 < 1%」。实测字符分布是长尾
   （3528 种不同字符，覆盖 99% 需 760 种、99.8% 需约 1400 种）。若严格只给 512 条，
   单字覆盖不够，UNK 率会破 1%。因此把「通用单字」计入 syntax 层，按累计频次覆盖
   99.8% 自动停止（`CHAR_COVERAGE_TARGET`），多字组合只取语料中频次 ≥3 的候选。
2. **`stdlib` 只有 182 条**：语料里真实存在的 `stdlib/**/*.light` 模块名 +
   `从 X 导入` 导入名合计就这些。卡面禁止「为了看起来更完整往词表里塞语料里没出现过的词」，
   所以宁可少放 586 条，也不造词。
3. **`ascii` 945 条**：95 个可打印 ASCII 全部在语料里出现过；标识符片段按频次 ≥4 取
   前 850 个，长尾片段收益递减，把预算让给中文单字覆盖。
4. **整体余量 29.20% > 建议的 17%**：符合「不要把 4096 塞满、留 15% 余量」，
   给后续新增 token 留了 1196 个位置。

各层样例（词表 `layers` 字段可读全量）：

- `l0`: `设 为 若 则 否 当 遍 断 跃 段 返 类 …`
- `syntax`: `\n 表 。 果 字 列 于 数 ： 加 回 如 …`（单字在前，多字组合在后）
- `stdlib`: `JSON核心 节点网络 大模型客户端 字符串工具 事件总线 哈希 文件系统 …`
- `ascii`: `空格 ! " # $ % & ' ( ) * + …` + `段落` 之外的英文标识符片段
- `control`: 见 3.3

### 3.2 L0 原子性结论

- `from lightprism.vocab import check_l0_atomicity` 对**全部 2900 个 token** 返回空列表；
- 44 个 L0 字各恰好占 1 个 token；
- 构建期 `_segments()` 在 L0 字处断开，`add()` 再兜底过滤「任何含 L0 字的多字 token」，
  所以语法组合、stdlib 名都不会把 `设/为/若/…` 粘连进去；
- 测试 `test_no_l0_char_inside_multichar_token` 把这条约束单独钉死。

### 3.3 控制 token 对齐（含一处文档/代码对拍）

复用 `TokenSpace` / `VALIDATION_CODES` / `STRUCTURE_MARKERS`，不另造清单：

- 结构标记 4：`<TASK> </TASK> <CODE> </CODE>`（`tokenizer.py::STRUCTURE_MARKERS`）
- 决策 token 19：`TokenSpace().decision_tokens()`（7 个决策点，3+3+2+3+3+3+2）
- 验证 token **9**：`VALIDATION_CODES` 实为 9 项（PASS、7 个 ERR、WARN=NON_CANONICAL、
  ERR=CHECKER_FAIL）—— **卡面表格写「8 个验证码 / control 31」与代码不符**。
  按「必须复用 `VALIDATION_CODES`、不许自己造一套」的硬要求，以代码为准，
  实产 32 条。若强行对齐 31，就得丢掉一个真实验证码，那才是违约。
- 布局与 `PrismTokenizer` 的 `ControlTokenLayout` 完全一致：
  `结构 → 决策 → 验证`，词表末尾连续区间 `[2868, 2900)`，`finalize()` 校验无空洞。
- `--check` 逐条比对数量、文本、顺序与三张 id 表；测试同项独立复算一遍。

## 四、UNK 率

**口径**：字符级。对每个语料字符，若不存在覆盖它的**单字** token 就计 1 个 UNK；
`UNK 率 = UNK 字符数 / 总字符数`。这是**保守上界** —— 多字 token 只会进一步降低
真实分词 UNK，不会抬高它。因此判据对「删单字 token」有判别力，不是恒 0 的假绿
（`test_unk_rate_is_discriminating` 用 `{"a":90,"b":10}` 反证）。

| 统计总体 | 字符数 | UNK | UNK 率 |
|---|---:|---:|---:|
| **判据口径**：513 个唯一 md5 语料文件（含被剔除文件，更严格） | 1,909,931 | 3,814 | **0.1997%** |
| 交叉参考：392 个 kept `.txt` 实时重算 | 1,312,606 | 3,770 | 0.2872% |

字符频次 `char_freq` 固化在词表 JSON 的 `corpus_stats` 里（附 `files_scanned` /
`files_unique_md5` / `files_kept` / `files_dropped` / `index_sha256`），所以**交付环境
没有原始语料也能跑 `--check`**；原始语料在场时会额外实时重算 kept 子集做交叉参考
（不参与判据）。两个口径都远低于 1%。
