## 五、监督信号：为什么这批日志能替代空标签 SFT

任务卡背景：本机 `--self-check` 在 363 条空标签 SFT 上得到决策密度 **0.083–0.096%**（方案要求 1–2%）、决策点 test 覆盖 **1/7**、`err_tasks` 仅 **8 条**。缺的是监督信号，不是 GPU 或超参。

本卡产出 `data/runtime/decisions.jsonl` 共 **29** 条，覆盖 **7/7** 个决策点、**12** 个决策选项、**3** 类真实验证码。每条记录都带：

- `source` + `source_sha256`：真实展开的 `.light` 代码体（`<CODE>` 内容）；
- `decisions` / `decision_tokens`：由**实际动作**映射的 `<D:...>`；
- `validation_code` / `validation_token_text`：由真实 checker 返回映射的 `<V:...>`；
- `checker_cmd` / `checker_cwd` / `checker_rc` / `checker_payload` / `checker_diagnostics` / `checker_stdout`：**可回溯到那一次真实 checker 调用**；
- `run_cmd` / `run_rc` / `stdout` / `expected_stdout` / `failure_reason`：真跑比对证据；
- `retry` / `edit_action` / `retrieval`：重试与编辑序列，可直接导出修复对。

即：`<D>` 从实际编辑动作、`<V>` 从 `light ai check` 日志、`<CODE>` 从实际展开源码，三者按 attempt 对齐，**无需人工标注**（方案一 §4.3 原本就这么规定）。这批日志是**监督信号源**，还不是最终训练序列；密度与配比需在后续导出阶段按 §8 的 1–2% 上限核算，本报告不宣称已达成训练指标。

## 六、纪律与边界

- 不训练任何模型、不用别的模型批量生成样本（T-0333 硬约束）；纯标准库 + light CLI。
- 不编造决策日志；`<V>` 不许模型自判，不许拿 `L0000` 冒充具体错误类型。
- 不拿 checker exit 0 当分子；不剔除失败分母；空输出 / 截断按失败计入。
- 预期执行结果由**独立于 .light 代码的 Python 语义**离线算出，运行时不参与代码生成，避免自己给自己判卷。

- 检索是零模型 BM25 + 关键词规则，报告如实标注；未命中的任务保留为真实失败样例。
