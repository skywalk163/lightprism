# LightPrism Demo 开发任务书 · 总纲

> 日期：2026-11-11 · 目标：做出能跑通的 demo 模型（输入 prompt → 输出光明代码 / JSON，
> 8GB 内存 5 代酷睿 CPU 推理，**≥ 200 tok/s**）
> 计划书事实源：[`lightprism/docs/Demo开发计划.md`](../../lightprism/docs/Demo开发计划.md)

## 一、三个必须先知道的硬事实

| 事实 | 数字 | 影响 |
|---|---|---|
| 200 tok/s 的规模上限 | **d=192 / L=6 / V=4096 ≈ 3.4M 参数** | 不是 1B，不是 300M。本机实测 283 tok/s |
| 可用语料 | **3.1MB / 508 个去重文件** | 必然过拟合，目标只能是「语法合法 + 模仿见过的模式」 |
| 本机 CPU | Xeon E5-2643 v2（2013 Ivy Bridge，**无 AVX2**） | 比目标机老，本机数字是保守下界，但**不能替代**目标机实测 |

**不要试图把 demo 做大。** 做大就达不到 200 tok/s，demo 就失败。

## 四、T-0329 是硬前置（否则全部派不出去）

**实测**：`hive/agents/*.json` 全部 17 份配置里，**没有任何一台登记了 `lightprism` 仓**。

当前各 agent 的 repos：
```
fb88-dsh         [hive, lightharness, light, lighthive, lightplugin]   ← 唯一 dispatchable
workbuddy        [hive, lightharness, lightmem, light, lighthive, lightplugin]
raccoon-ic6      [hive, light, lighthive, lightmem, lightharness]
...
```

`hive.py` 的 `draft_lint` 会在 repo 未被任何 agent 登记时报错「这张卡永远派不出去」。

所以 T-0329 做两件事：

1. 给至少 2 台 agent 的 `repos` 加上 `lightprism`（本地路径 `/home/skywalk/dswork/lightprism`）；
2. 把 `lightprism` 同步到 Gitea（`http://192.168.1.5:3000/skywalk/lightprism` 已存在）。

## 五、并行时的三条纪律

1. **同一台机器不要同时跑 T-0331 bench 和 T-0332 训练** —— 会抢 CPU 核，
   让 200 tok/s 的测量失真。T-0332 标了 `exclusive: true`，dispatch 会跳过同机其他卡。
2. **词表是全局约定**：T-0330 出词表前，T-0331 只能做结构（不能定嵌入层尺寸），
   T-0332 完全不能开工。
3. **T-0334 只读**：验收 agent 不许改被测代码，发现问题写报告另开卡。

## 六、验收怎么算通过

`docs/Demo验收报告.md` 里 V1—V7 七条，**全部通过才算 demo 成功**。其中：

- V1—V5、V7 可自动验；
- **V6（目标机实测）必须真机**，拿不到就标 `blocked` 并说明，不许拿本机数字冒充。

**任何一条没通过，demo 就不算完成**，如实报告比硬凑数字有价值。

## 七、不在本批范围

- 64K 词表（另开卡，demo 验收后）
- 1B / 300M 模型（200 tok/s 达不到）
- RLVR 阶段（需 lightharness 环境）
- 通用编程能力（3MB 语料做不到，不要承诺）

## 八、给领卡 agent 的提醒

1. **先读计划书**（`lightprism/docs/Demo开发计划.md`），特别是 §1 的三个硬事实；
2. 卡里写的「禁止」不是建议，是硬约束（尤其「不要编造输出样例」「不要挑成功样例」）；
3. 跑不完就如实标 `blocked` 并写清卡在哪，**不要交半成品冒充完成**；
4. 每张卡的完成标准都给了可执行命令，自测通过再 submit。
